Тренажёр 08·1 · Разбор готового SQL-кода

Читаем чужой скрипт: таблицы, ключи, связи, данные и запросы. Каждый запрос выполняется прямо в браузере.

Это учебный тренажёр без оценки: ответы никуда не отправляются, а попытки не ограничены. Писать SQL с нуля здесь не нужно — задача в том, чтобы понять готовый скрипт и уметь объяснить, какую задачу решает каждый запрос. Можно разбирать самостоятельно или вместе с ИИ, но каждое объяснение стоит проверять запуском запроса.

Выберите вариант

Во всех вариантах одинаковая структура скрипта: DROP TABLE → CREATE TABLE → INSERT → пять запросов SELECT. Отличаются предметные области.

Шаг 1. Таблицы и ключи
Отметьте для каждого поля, является ли оно первичным ключом (PK) — однозначно определяет строку своей таблицы, — и внешним ключом (FK) — ссылается на строку другой таблицы. Одно поле может быть и тем и другим. Подсказки ищите в тексте CREATE TABLE: слова PRIMARY KEY и REFERENCES.
Паспорт таблиц
Типы данных и ограничения, прочитанные из скрипта. Так выглядит описание базы, которое стоит иметь перед любым запросом.



Шаг 2. Связи между таблицами
Определите тип каждой связи. 1 : M («один ко многим») — одной строке слева соответствует много строк справа. M : M («многие ко многим») — много с обеих сторон; такая связь всегда хранится через промежуточную таблицу. 1 : 1 — строго по одной строке с каждой стороны.
Схема связей
Обозначения: «1 — M» читается «одна строка слева — много строк справа». У каждой таблицы показаны ключи.



Шаг 3. Что добавляют INSERT
Скрипт уже выполнен. Посмотрите, что лежит в таблицах после всех INSERT, и ответьте на вопросы о порядке заполнения и пустых значениях.
Эксперименты с ограничениями
Каждая кнопка выполняет одну команду на свежей копии базы. Посмотрите, что база разрешает, а что нет.



Шаг 4. Запросы SELECT
Для каждого запроса: определите бизнес-задачу, предскажите число строк и только потом выполните. Кнопки «Что если…» меняют одну часть запроса — так видно, за что она отвечает.



Шаг 5. Проверка объяснения ИИ
Как проверять объяснение ИИ
  • Выполните запрос и сравните число строк с тем, что обещает объяснение.
  • Найдите в запросе каждую часть, о которой говорит объяснение. Если её нет, утверждение придумано.
  • Отдельно проверьте строки без пары и пустые значения: что с ними делают JOIN, COUNT и AVG.
  • Сверьте название показателя с формулой: «потратил» и «сумма всех заказов» — разные вещи.
