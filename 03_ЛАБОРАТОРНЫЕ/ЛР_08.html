Зачем это нужно

Реальные данные почти никогда не лежат в одной таблице: студенты, потоки, преподаватели и результаты хранятся отдельно и связаны ключами. SQL позволяет собрать ответ прямо в базе: вопрос → таблицы → ключи → запрос → проверка результата.

Как будет устроена работа

  • Индивидуальный вариант — по табельному номеру: факультет, дисциплина, преподаватель, аналитический маршрут и пороги отбора.
  • Задания 1–2. Выборка и агрегация: запрос по своему факультету, паспорт дисциплины (результаты по статусам, средний балл и средняя оценка).
  • Задания 3–4. Соединение таблиц: нагрузка преподавателя через LEFT JOIN, анализ групп с порогом отбора.
  • Задание 5. Аналитический маршрут варианта.
  • Задание 6. Собственное наблюдение — проверяемый тезис, подтверждённый запросом.
  • Отчёт. PDF: SQL-скрипт, результаты выполнения, 2–3 вывода по данным и декларация использования ИИ.

Как подготовиться

Перед работой в DBeaver пройдите тренажёр 08·2: у учебной базы та же структура, что у основной, только данных меньше. Запросы из тренажёра переносятся в DBeaver почти без изменений — достаточно указать схему:

SELECT student_name, group_code
FROM grades.students
WHERE faculty = 'ФЕН'
ORDER BY student_name;

Различия PostgreSQL, которые стоит помнить: при сортировке DESC пустые значения встают первыми (добавляйте NULLS LAST или фильтр IS NOT NULL); если ROUND(AVG(…), 2) выдаёт ошибку о типе, приведите значение к numeric: ROUND(AVG(…)::numeric, 2); столбец из SELECT без агрегата обязан быть в GROUP BY.
